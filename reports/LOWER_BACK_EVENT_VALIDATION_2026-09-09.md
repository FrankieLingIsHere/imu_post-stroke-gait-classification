## Algorithm and input contract

Installed mobgap **1.2.0** in the existing
`C:/Users/frank/.venv-cu130/Scripts/python.exe` environment; installation report
and environment versions are saved. No existing NumPy/Pandas/PyTorch upgrade was
required. The selected components are
[GsdAdaptiveIonescu](https://mobgap.readthedocs.io/en/v1.2.0/modules/generated/gait_sequences/mobgap.gait_sequences.GsdAdaptiveIonescu.html)
and [IcdShinImproved(axis='norm')](https://mobgap.readthedocs.io/en/v1.2.0/modules/generated/initial_contacts/mobgap.initial_contacts.IcdShinImproved.html),
with published package defaults and no tuning to our labels. Both use acceleration
magnitude; gyro columns satisfy the package frame schema but do not affect these
algorithms, verified by a test. This is a composition of components, not validation
of the full Mobilise-D pipeline.

Inputs are the provider's **processed LB_Acc_X/Y/Z in m/s²**, retaining gravity,
on its annotation timeline. No further gravity subtraction, rescaling, filtering
or interpolation is applied. Trailing all-acceleration-NaN padding is removed;
interior nonfinite inputs would be rejected. This is autonomous detection from a
prepared signal, not an independently validated raw-device preprocessing system.

The [provider's metadata schema](https://www.nature.com/articles/s41597-025-05959-w/tables/5)
defines each event pair as toe-off then heel-strike. We compare **the second
element**, not the first. The [dataset article](https://www.nature.com/articles/s41597-025-05959-w)
states that events and turns were generated by algorithms. Thus this experiment
measures agreement with supplied annotations, not independent force-plate or
motion-capture accuracy. It does not establish paretic-side classification.

## Executed modes and measurement definitions

- **Autonomous:** full prepared lower-back recording → detected gait sequences →
  detected contacts and per-bout cadence. Only signal and sampling rate enter
  prediction. Neither diagnosis nor reference events/bounds enter this mode.
- **Reference bouts:** detector receives the two supplied straight-walking
  intervals. This deliberately isolates contact detection from segmentation and
  is not an autonomous performance claim.

For comparable evaluation, both modes' contacts are scored in identical reference
straight-walking regions, including the final heel-strike sample. Turn contacts
are excluded from this straight-walking score. One-to-one ordered event matching
uses a fixed 150 ms tolerance; duplicate detections cannot receive duplicate
credit. Reported F1 is calculated from pooled trial counts within each participant,
then averaged equally across participants.

The primary **step-count-derived cadence error** is
`abs(predicted count - reference count) * 60 / reference straight duration`,
averaged over trials within each participant, then across participants. This
includes complete detection failures and boundary/step-count errors. It is not
the same as instantaneous or inter-contact-interval cadence error. The adapter
also exports conventional per-bout cadence `60*(N-1)/(last-first time)`; accuracy
of that distinct quantity has not been established by the count-error table.

Output coverage means at least two contacts detected in reference straight
regions, not valid timing or correct cadence. Autonomous contacts outside the
reference walking envelope are separately reported as idle detections; turn
contacts are not mislabeled as idle. These short protocol idle periods do not
constitute broad nonwalking-activity validation.

Preset engineering acceptance required, separately for healthy/stroke/other:
participant-macro F1 >= .85, count-cadence MAE <= 5 steps/min and trial coverage
>=95%. These are project admission rules, not clinical standards.

## Concrete timing defect exposed and its scope

The initial native-row implementation stopped at HS_2_1: 2,980 raw lower-back
rows, packet counters spanning a longer timeline, and a reference heel-strike at
sample 3,005. Indexing raw rows with annotation indices is invalid when packets
are missing. The completed adapter uses the provider's prepared timeline instead;
the aborted raw protocol is preserved as `failed_raw_timeline_protocol.json`.
A second pre-completion stop on PD_15_13 led to explicit invalid-reference
accounting, without changing detector settings or adjusting event tolerance.

A full packet census finds 520 local trials with genuine counter gaps. Of the
previous conditional-comparison inputs, **513 trials from 115 participants** have
gaps. Its existing helper indexes raw rows directly, so raw RMS/bound-restricted
interpretation for the mixed cohort is provisional pending aligned extraction.
Its annotation-only cadence/stride calculations do not acquire this row-index
defect. **Zero trials in its strict device/protocol-matched subset have gaps**;
the matched RMS AUROC .801 healthy contrast versus .449 other-pathology contrast
is not explained by this specific packet-gap issue. This does not establish that
all other alignment or preprocessing questions are resolved.

Use `packet_alignment.csv` for these counts. The initial `input_ledger.csv`
`native_counter_gaps` field counted floating-point increments slightly above one
as gaps; the follow-up diagnostic corrects this with a >1.5 increment threshold.
This bookkeeping correction did not change any detector input or prediction.
Historical classification/feature artifacts were preserved, not silently replaced.
No causal explanation of the frozen CNN's external false positives is claimed.
